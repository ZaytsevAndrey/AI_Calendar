# Deploy (Render + Neon)

Free hosting for this monorepo: **Render** (API web service + static frontend) and **Neon** (Postgres). GitHub Actions runs CI; Render auto-deploys **`master`**.

Local development is unchanged: SQLite (`backend/db.sqlite`) and `npm start`.

## What is free vs what is not

| Piece | Choice | Notes |
|-------|--------|--------|
| Frontend | Render static site | Free CDN, HTTPS, `*.onrender.com` |
| Backend | Render web service (`plan: free`) | Sleeps after ~15 minutes idle; cold start ~1 minute. **750 instance hours / month** |
| Database | [Neon](https://neon.tech) Free Postgres | Durable (unlike SQLite on Render’s ephemeral disk). Render’s own free Postgres **expires after 30 days** — do not use it |
| CI | GitHub Actions | Tests + production build on PR/push to `develop` and `master` |
| CD | Render Blueprint (`render.yaml`) | Deploy on each commit to `master` |
| Custom domain | Later | Attach CNAME on Render when you want a subdomain |

Schedule **jobs** stay in-process (`setInterval` every 2s). They run only while the API instance is awake (user-triggered generate is fine). Render Cron Jobs are paid — not used.

## One-time setup

1. Create a [Neon](https://console.neon.tech) project. Copy the connection string (`postgresql://…?sslmode=require`).
2. Create a [Render](https://dashboard.render.com) account and connect GitHub repo `ZaytsevAndrey/AI_Calendar`.
3. **New → Blueprint** and select this repo (uses root `render.yaml`). Confirm branch **`master`**.
4. When prompted, paste:
   - `DATABASE_URL` — Neon URL
   - `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`
   - `GOOGLE_REDIRECT_URI` — `https://<ai-calendar-api-host>/google-calendar/callback`
5. After the first deploy, copy the two public URLs (API and static site). In [Google Cloud Console](https://console.cloud.google.com/apis/credentials):
   - Authorized **JavaScript origins**: frontend URL
   - Authorized **redirect URI**: exact `GOOGLE_REDIRECT_URI`
6. If the frontend was built before the API URL existed, **Manual Deploy → Clear build cache & deploy** the static site once.

`FRONTEND_URL` and `REACT_APP_API_BASE_URL` are wired in `render.yaml` from each service’s `RENDER_EXTERNAL_URL`.

## URLs after deploy

- App: `https://ai-calendar-web.onrender.com` (suffix may be added if the name is taken)
- API: `https://ai-calendar-api.onrender.com`
- Health: `GET /health` → `{ "status": "ok" }`
- Swagger: `https://<api-host>/api`

## Git workflow

| Branch | CI | Deploy |
|--------|----|--------|
| `develop` (PRs and pushes) | GitHub Actions: tests + build | No |

Merge to `master` when you want production updated.

## Environment (production)

Set on the **API** service (Blueprint prompts the secrets):

| Variable | Purpose |
|----------|---------|
| `DATABASE_URL` | Neon Postgres URL |
| `JWT_SECRET` | Generated by Render if unset |
| `FRONTEND_URL` | From the static service |
| `APP_URL` | From the API service |
| `GOOGLE_*` | OAuth — redirect URI must match Google Console |
| `TYPEORM_SYNC` | `true` on first empty database; schema is applied automatically |

Frontend **build-time** variable:

| Variable | Purpose |
|----------|---------|
| `REACT_APP_API_BASE_URL` | Axios base URL (from the API service) |

## Custom domain (optional, later)

On Render: each service → **Custom Domains** → add e.g. `calendar.yourdomain.com` (static) and `api.yourdomain.com` (API). At your DNS host, CNAME those names to the `onrender.com` hostnames Render shows. Then update Google OAuth URIs and trigger a frontend rebuild so `REACT_APP_API_BASE_URL` stays correct (or set it explicitly).

## Limits to expect

- First request after idle: API cold start.
- Free instance hours exhausted: API suspends until next calendar month.
- Neon Free: storage and compute quotas; compute scales to zero when idle (next API request waits on DB wake-up too).
- Do not rely on files written next to the API process — the disk is not persistent. All app data must live in Postgres.

## Copy local SQLite into Neon

Run this **on your machine** (Render does not have `db.sqlite`). It wipes production tables, then copies current product tables. Leftover local-only tables (`categories`, `migrations`, `schedule_undo_snapshots`) are skipped.

From `backend/` (PowerShell):

```powershell
$env:PROD_DATABASE_URL="postgresql://USER:PASSWORD@HOST/neondb?sslmode=require"
$env:CONFIRM_OVERWRITE="yes"
npm run copy-db:prod
```

From `backend/` (Command Prompt / cmd.exe):

```bat
set PROD_DATABASE_URL=postgresql://USER:PASSWORD@HOST/neondb?sslmode=require
set CONFIRM_OVERWRITE=yes
npm run copy-db:prod
```

`PROD_DATABASE_URL` is the same Neon string as Render `DATABASE_URL`. After the copy, sign in again on the deployed site: production `JWT_SECRET` is not the local one. Google Calendar tokens on the user row are copied, so an existing Google connection should still work once you log in.
