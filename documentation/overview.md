# Project overview

## Purpose

**AI Calendar Assistant** is a web app for time planning with **day phases**, **tasks** (deadline, fixed / flexible / recurring settings; priority soft-deprecated for placement), personal **sleep/wake** settings, and **Google Calendar** integration. **Intelligent scheduling** seats movable tasks through the **placement step** ([spec-incremental-placement.md](spec-incremental-placement.md); [conflict rules](spec-conflict-rules.md)), respects anchors (manual slots, fixed blocks, external events on connected calendars), and supports splitting. Generate / Clear / Undo / Suggestions are removed. Fully ended app events stay and show in gray. Recurring series stay alive via a **background horizon append** (placement writes missing days; past Problematic copies are purged). Failed Google writes retry from `pending_google_writes`. Below **768px** the shell is a bottom tab bar and the calendar opens on **day**; week is one column under a 7-day strip, month is day numbers with a dot. **Create** and voice sit in one row above that bar (one tap each). From **768px** the header layout is unchanged, including a sideways week grid between 768px and the wide layout.

## Stack

### Frontend

- React 18, TypeScript  
- Redux Toolkit + **RTK Query** (`@reduxjs/toolkit/query`) for part of the API  
- Axios (`src/api/axios.ts`) with `baseURL` from `REACT_APP_API_BASE_URL` (see [setup-and-build](setup-and-build.md))  
- React Router, React Hook Form, react-toastify (IDE-dark toasts: type colors, title + detail; task CRUD includes name and scheduled time)  
- Build: **Webpack** (`npm run build` in the `frontend` package)  
- Tests: Jest (`frontend/src/**/*.spec.ts`, e.g. toast date copy)

### Backend

- NestJS 10, TypeScript  
- **Fastify** adapter (`@nestjs/platform-fastify`)  
- TypeORM + **SQLite** locally (`db.sqlite`) or **Postgres** when `DATABASE_URL` is a `postgres://` URL  
- JWT (Passport), Google OAuth 2.0, Google Calendar API  
- Swagger UI at `/api`  
- Tests: Jest (`backend/test/`, `*.spec.ts` in modules)

## Features (as implemented)

- **Sign-in** is OAuth via **Google** (live), with **Microsoft** on the login screen when server credentials are set ([integrations](integrations.md)). **Apple is not a login option** — iCloud Calendar is linked only from Settings (CalDAV + app-specific password). Password registration, login, reset, and email verification are removed. Google sign-in stores default wake `07:00` / sleep `22:00` and sets `googleCalendarLinked`; that flag is not a second connect step. Linked identities (`user_identities`) share one app account across providers. **Delete account** (Settings) is a two-step confirm: warn about removing app-created Google events and the dedicated app calendar, then type `DELETE` or the account email; Google cleanup must succeed before local wipe (`DELETE /auth/account`). A user with no phases stays on `/setup/phases` with no app navigation until they save wake and sleep, then either apply a day-shape preset or skip to Sleep + Focus. The SPA axios client single-flights `POST /auth/refresh` on any 401 (including schedule job polls / `move-event` that call axios directly), retries once, and logs out only when refresh fails.  
- **Companion** (UK: Помічник): floating movable/resizable panel on desktop (calendar stays usable); bottom sheet on phone. A switch chooses **Companion** (dialogue, can ask) or **Fast create** (a new task from one phrase; one question only when it cannot be saved; the choice is kept in the browser). Mic (on by default) + typed composer → STT or text into `POST /voice/turn`. Read tools ground Q&A; writes are client-executed intents (same conflict sheet). Confirm / day-plan show calendar-style **preview cards** before Apply. Session is in-memory per open widget. Spoken replies use Azure Speech when configured, otherwise local Piper, otherwise the browser voice. See [spec-voice-agent.md](spec-voice-agent.md), [features/companion-panel.md](features/companion-panel.md). One utterance may carry several writes plus a question (one Apply, per-item status after); "plan my day" runs a short interview, seats tasks via an engine dry-run, and lets the user edit the plan by voice before Apply.
- **User settings:** wake/sleep, weekends, Google Calendar flags, `allowSplitScheduling` / `minSplitMinutes`, **`defaultTaskDurationMinutes`** (length of a new task when none is named; form and voice), **`fixedEventBufferMinutes`** (minutes placement keeps free before and after each fixed task and each external event on a visible connected calendar; 0 is off; the gap is used only when the task would not fit otherwise), IANA **`timeZone`** (filled once on first login, editable in Settings; source of truth for the scheduling engine), **`language`** (`en` | `uk`; UI chrome, calendar date labels, toast when-lines, push, and schedule suggestions), **`speechLanguage`** (`en` | `uk`; voice STT/TTS and agent spoken replies — independent of UI language), **`speakVoiceReplies`** (client TTS for voice clarify/confirm/result/Q&A), **`hiddenGoogleCalendarIds`** (which Google calendars the Calendar page hides), **`syncGoogleDeletions`** (default off; when on, a gone linked external event deletes the local task on retry), **`syncTargetCalendars`** (outbound sync targets or empty = nowhere), dismissible warnings for flexible / unschedule / write-back  
- **Phases:** per-user CRUD (JWT), overlap validation, default **Sleep** + **Focus hours** from wake/sleep when the user has no phases, lifestyle presets that tile wake-to-sleep (morning blocks, a fill through to the evening block; under 30 minutes is dropped), phase calendar UI  
- **Tasks:** CRUD, statuses, priorities, optional From/Until window (`earliestStartTime` + `deadline` + `scheduleTimeZone`), one optional phase, split / recurring flags, optional `recurrenceWeekDays` / `eligibleWeekDays`; **fixed** blocks require scheduled start/end; movable tasks may set a preferred start. **Unscheduled** (`isUnscheduled`) is a separate inbox on the Tasks page: no slot, no Google sync until the user schedules it. Completed or canceled Unscheduled rows stay out of the inbox and off the Calendar overlay. Cards use **icon-only** actions (**Done**, **Skip** / cancel, **Do now** / from-now window + placement, **Schedule** / schedule form with phase and window, **Edit**) and icon meta for phase, earliest, and deadline (tooltips / aria-labels); overdue gets a red edge. Deadline/window no-fit after placement parks here for non-recurring tasks (not Problematic); recurring no-fit always parks as Problematic. **Problematic** (`scheduleState`: `none` | `problematic` | `resolved`) is distinct from Unscheduled and from task status. `problematic` is work that fell out of schedule after Generate overflow or an unanswered conflict; Calendar shows a banner and sheet (Open / Move / Skip / **Place on top**). **Place on top** (`scheduleState: resolved`) keeps the task on the calendar as a second layer: if an original/preferred interval exists it is reseated; if not, a default slot is invented (civil day + phase start or 09:00, duration from estimate). New claims look for another hole. Concurrent Place on top / Skip keep per-row loaders. **Move** opens a snap-scrolling day timeline of free 15‑min slots (`GET /schedule/free-slots`): recurring days become a one-off + skip; non-recurring tasks are placed in place as fixed. Preferred-on-fixed opens a **shared conflict options** sheet after create/update/Generate/**Voice**/drag (`conflicts[]` on the write, or a replan job) with `place_on_top` / `move_new` / `skip_occurrence` / `leave_problematic` (and `move_other` when offered); dismiss parks as Problematic; a second utterance can pick an option. Skip from Problematic skips the parent series day then deletes the copy (`{ deleted: true }` so the client drops cache). Deleting a series also removes park copies that point at it via `parentSeriesId`. Voice **do now** clears Unscheduled and opens a from-now window through the same replan path. Each section filters on its own: Unscheduled by name, status, and overdue; Scheduled by name, status, phase, fixed / flexible / recurring, and overdue (plus sort). A filter in one section does not change the other. Tasks that share a `seriesGroupId` (clock-split series, “this and following” tails, detached one-offs, Problematic copies) render as one group: the primary series member uses the same full task card as a lone task (its Delete removes every group member immediately, no confirm), with expand/collapse for nested One-off / Problematic / sibling parts; nested rows keep per-member delete (still with confirm). Series hole search seats nearest to preferred (not earliest) so days cluster into fewer clocks. The Recurring schedule filter includes any task with `seriesGroupId`, not only `isRecurring`. Overdue is a past deadline on a task that is not completed or canceled. The create/edit form is a single **TaskForm** with **Flexible / Fixed / Recurring / Unscheduled** presets; preferred-start offers only times inside the selected phase (including overnight windows) and clears when a phase change leaves the current time out of range; clickable phase chips (not a dropdown); expandable Google event options (location, color, visibility, show-as, reminders) stored on the task and applied when a Google event is created. Native Google events that are not linked to a task still use **EventForm**. Calendar day-click prefills that civil day’s From/Until in Settings IANA `timeZone`. Clicking an app-generated calendar event opens TaskForm for the linked task. Edit modal **Delete** confirms for one-offs; for recurring with an opened occurrence it asks this day / this+following / entire series (same as calendar hover-delete); recurring opened from Tasks without an occurrence deletes the entire series after confirm. Task create/update/Done/Skip/delete use a staged **mutation progress** toast (title = task name; Saving → seating → Google → Done). Extra one-shot success toasts for those paths are omitted (Google-only event edits and recurring-reschedule extras still use a short success toast). **Voice:** mic on Tasks/Calendar records audio, Groq Whisper transcribes (uk/en/ru auto), an LLM maps speech to a task using Settings IANA `timeZone`. Immediate create when a name exists (defaults fill the rest); cancel during a follow-up still creates when a name was already understood; only an unintelligible / missing name asks one follow-up question. The same recording can complete, skip, or move the current or a named task. Done on a repeating task skips today's occurrence. An open slot moves like a drag; no open slot updates From/Until and replans. Settings **Ask before voice commands** is off by default.  
- **Habits:** soft-disabled for MVP. Code and DB rows remain; product surface is off (no nav/page/calendar chips/Now strip, no voice `habit_*`, no schedule busy, no habit push). `GET /habits` returns an empty list without Google backfill; writes return 410. Existing Google habit events are left as-is. Re-enable after the product shape is decided ([roadmap](roadmap.md)).  
- **PWA:** installable (manifest + service worker + icons). Android Chrome shows an install prompt; iOS uses Share → Add to Home Screen. **Reminders** (Settings, off by default) are Web Push: one notice in the half hour before each timed task/calendar block. All-day events are skipped. On iPhone, add the app to the Home Screen first. A start that has already passed is not sent when the free API wakes up.  
- **Calendars (multi-provider):** Google and Microsoft (OAuth) plus Apple iCloud (CalDAV from Settings) share a `CalendarProvider` interface. Replan and **clear schedule** create/update/delete linked Google events when `googleEventId` is set. **Calendars** on the Calendar page hides calendars (provider sections → calendars). Default stays primary + the app calendar + calendars selected in Google, plus every connected Microsoft and Apple calendar. The app calendar stays visible. Hidden calendars are also left out of placement busy time. Thin **`calendar_event_overlays`** store fixed/flexible only after the user changes type on an external event; Unscheduled removes the external event and creates a local Unscheduled task (with a dismissible warning). Calendar chips show **type icon** + **provider/calendar badge** (logo + calendar name); type is editable via click menu except recurring. Day and week time grids show the **personal day**: from wake until sleep, including the hours after midnight when sleep is after midnight (those hours sit at the bottom of that day, not as a strip at the top of the next civil morning). Sleep is omitted. Hours that no schedulable phase covers are omitted too; with no phases the whole wake-to-sleep window stays. Drag a timed event to move it or drag its edges to resize it (15-minute steps; thin resize handles). Cards show the title (no start clock on the chip); hover reveals delete. A click opens an event preview (title, time, notes, location, recurrence) before Edit or Delete; repeating app tasks pick this day, this day and following, or the entire series from those buttons. Chip and list Delete stay as shortcuts. Completed app tasks stay on the grid with a done badge / strikethrough (Google keeps the event when status is completed). Month chips follow the same personal day.  
- **Schedule:** scheduled tasks via the placement step on the **Calendar** page (`/calendar`). Horizon append and past-Problematic purge run on an hourly tick. On a phone, create a task and voice stay one tap in the bar above the tabs. Scheduled task cards show priority, status, phase, duration, and deadline as tinted pills; Unscheduled cards use icon meta instead. Each Tasks section keeps search and the filter control on one row. The page also has a **Now / Next / Unscheduled** strip (today in Settings IANA `timeZone`): soft-tint columns, kind icons on cards, icon actions, and a click that opens the same event preview as the grid (Unscheduled via a local preview event). Now/Next keep Done on non-recurring app tasks, and **Skip** on a still-open app slot or recurring instance. Unscheduled is a scrollable today inbox with Done / Skip / Do now / Schedule / Edit. The Tasks page has a separate **Unscheduled** section for inbox items (`isUnscheduled`) that stay off the calendar until Done, Skip, Do now, Schedule, or Edit. Event preview also offers **Done** for one-off app tasks. Done sets `completed` and keeps the seated calendar block (styled as done); Skip on a scheduled occurrence removes only that occurrence/slot and leaves the task `todo`. Recurring Skip is remembered so placement will not put that day back; a one-off Skip can be placed again on the next replan. A silent replan after create will not place a task that is already completed. Recurring horizon rewrite keeps existing open seats when a rewrite would otherwise wipe them first.

Implementation notes:

- **`event-phases`** module (`/event-phases/*`) links calendar events to phases; public CRUD is **`/phases`** (authenticated, scoped by user).  
- The TypeORM `Task` entity uses the **event-phases** `Phase` entity for relations (same `phases` table as the `phases` module).

## Scheduling (intelligent engine)

Core logic lives in `backend/src/modules/schedule/intelligent-scheduling.engine.ts` and runs inside **schedule jobs** (`ScheduleJobService` / processor). Summary:

- Movable tasks: TODO, not `isUnscheduled`, not `scheduleState` `problematic`, not fixed external, not `eventType` **fixed**. Placement target: [spec-incremental-placement.md](spec-incremental-placement.md) (seat once; move only the overlapped task). `PlacementStepService.place` seats one claimant and does not call `engine.run`. Create and geometric edit call that step. Cosmetic edit updates the task and the same Google event. Drag, skip, delete, complete, and cancel do not enqueue `full_replan`. Recurring expand seats each horizon day on its own slot; different clocks become sibling tasks linked by `seriesGroupId` (re-merge when a member returns to a sibling series clock; meta edits break membership). Dragging one day of a recurring task asks this day or the whole series: this day becomes a one-off in the same group, and the whole series ends before that day and continues as a new recurring task. A freed hole seats every problematic task that fits, oldest first. `engine.run` does not write slots. Inboxes and option ids: [spec-conflict-rules.md](spec-conflict-rules.md). Priority ignored. Non-recurring remaining work = estimated minutes minus fully ended auto slots; if nothing remains, Generate does not place the task again. A From/Until or deadline that is already over is skipped (no error), not forced into a new day.  
- **Time zone:** `user_settings.timeZone` (IANA). Wake/sleep, phases, weekdays, and the planning horizon are civil clocks in that zone. Empty/invalid → `UTC`. Changing the setting does not rewrite already stored UTC instants.  
- **Phase window:** one optional phase, intersected with wake/sleep and weekend rules. Recurring days = task `recurrenceWeekDays` ∩ phase `weekDays`.  
- **Anchors:** non-auto-generated scheduled rows, fixed tasks, in-progress auto segments, **fully ended** auto-generated slots (kept across replan/clear), and fixed-external tasks block time. **`fixedEventBufferMinutes`** also keeps that many minutes free on both sides of fixed tasks and external events from every visible connected calendar (Google, Microsoft, and Apple). Hidden calendars are ignored. Free / transparent events and the app’s own synced copies are not double-counted. All-day events block the scheduling engine; the Problematic slot picker uses timed events only. Ended flexible slots are not padded. Generate uses the gap only when the task would not fit otherwise.  
- **Placement (no Generate):** finished app events stay and show gray on Calendar. Task create and geometric edit seat through the placement step and return a mutation `jobId` (`saving` → `placing` → `syncing` → `done`). Horizon days append via placement; Google sync uses `pending_google_writes` on failure.  
- **Splitting** when the task and user settings allow it (`allowSplit` ∧ `allowSplitScheduling`, `minSplitMinutes`). Peer displacement by priority is **out**; conflict options / Problematic replace bumping (see conflict rules).  
- Output: persisted `scheduled_tasks` (auto-generated), task-level scheduled range, job **diff** / warnings / errors.  

For HTTP details see [api-reference](api-reference.md). Placement/conflict contract: [spec-conflict-rules](spec-conflict-rules.md). Engine/queue/Google: [spec-intelligent-scheduling](spec-intelligent-scheduling.md).
